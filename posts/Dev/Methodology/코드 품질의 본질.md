코드 품질의 본질
해당 영상에선 단순한 Framework 를 통해 코드의 본질을 이해하고자 한 과정을 소개하고 있다.
### 코드 품질의 목적은 -> 이해다.
엄청 큰 코드 -> 완벽히 설명할 수 없음, 무한한 복잡성을 가짐
그래서 우리는 모듈 단위로 동작을 쪼개서 -> 일정 범위를 이해했음

예) Chromium project 는 복잡하게 얽힌 구조를 가지고 있지만, 그 일부분인 URL Parser 를 이해할 수 있음
### 프로그래머는 다음 2가지를 할 수 있으면 문제가 없음
- 프로그램이 어떻게 동작하는지 알기
- 어떻게 고칠 수 있는지 알기

### 프로그램을 고칠 때 문제가 생길 수 있는 부분
- 버그가 생긴다
- 수정이 힘들어진다 (기능 하더라도)

요 두 부분은 한 곳에서 문제가 생기면 서로 문제를 일으키면서 복리로 커져요

### 일회용 소프트웨어
LLM 이 등장하면서 생긴 개념이다. 다른 요소가 의존하는 접점을 만들지 않으면서 적은 사람만 사용하는 경우를 말한다. 

일회용 소프트웨어가 되면 코드 퀄리티는 중요하지 않아지는 부분이다. 문제가 생겨도 문제가 없기 때문이다.

고장나도 되는 Software 를 만드는 방법도 많다. 연결을 끊고, 격리하고, 백업을 만들고 기타 등등
### 반대 자리 
Durable Software 는 Software Engineer 를 계속 필요로 할 것이다.
