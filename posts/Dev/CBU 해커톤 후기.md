### 시작 전
단순히 웹에 아이디어만 세우면 끝나는 딸깍 해커톤이 될 줄 알았는데, 보안이 주제로 나오고 굉장히 다양한 주제를 나열해주셔서 당황스러웠다. 

### 과정
한분이 AI 사용중 연구 자료를 아무렇지 않게 넣는 것을 보면서 해당 문제를 해결하기로 제안해주셨고, Chat Interface 에서 입력 전 몇가지 정보를 필터링 해주는 기능으로 구체화 해나갔다.

신호등을 이용해서 현재 상태가 안전한지, 정보가 어떻게 활용되는지 바로 연결해서 보여주는 Chrome extension 기반의 서비스와, 중앙에서 규칙과 통계 등을 관리 가능한 기능을 넣어 구현하기로 결정

구현 목표는 개인이 사용할 땐 기본적으로 개인정보 필터링이 되고, 중앙 관리 시스템에서는 주요 정보를 업로드 하는 것을 막기 위한 여러 장치를 추가할 수 있는 형태로 구상했다. 

### 결과
결과물을 제대로 완성하는데 실패했다..

### 원인 분석
#### 구현 목표가 명확하지 않았다.
"어떤 데이터 -> 어떻게 가공 & 어떻게 적용" 이정도 흐름은 제대로 잡고 갔어야 했지만 그렇지 못하고, AI 한테 결정을 맡겨버리면서 구현이 산으로 갔다.
"이런 기능 구현해" 정도론 힘든 구조였던 것 같다. 

또 백엔드 구조가 Spring dashboard server 와 Python server 를 각각 구현해 동기화 하는 등 불필요한 기능이 너무 많았던 것도 컸다.
(Java + Python + JS 가 모두 사용되는 혼종이 되었다)

모듈 형식도 넣었는데, 그냥 중복 언어별 중복 기능 구현 문제가 생겼다.

한번 코드가 산으로 가니 여러 문제가 발생하였고 수정 시간은 부족했다.
#### AI 가 생각보다 많이 느렸다.
평소에는 Linux machine 에 Tmux 켜두고 몇 시간씩 켜두는 것이 문제가 되지 않아서 시간에 대한 인식이 부족했다.
그래서 생각보다 느린 구현 속도가 발목을 잡았다. 

처음 생각은 Frontend 를 빠르게 만들어 다같이 검토하고 재구현 빠른 Iteration 을 상상했지만, 기본적인 구현에도 많은 시간이 소요 되었다. 
~~(GPT 6.1 sol, astra 너무 느려요)~~
#### 주제를 더 뾰족하게 잡아야 했다.
개인과 기업(연구소) 양방향을 잡으려고 했다 보니 발표할 때 목표를 명확하게 전달하기 힘들었던 것 같다. 

주제는 괜찮았던 것 같지만, 짧은 시간 안에 핵심을 담아 전달해야 했는데 기억에 남기기 힘들었을 것 같다.

주제 검증 PoC 관점에서도 문제가 많았음

- 추상화 레이어로 모듈화 되어야 할 것들이 하나의 함수가 되어버리고, 기능을 명확히 규정할 수 없는 상태가 됨
- 기능이 중복 개발되어 같은 부류의 기능이 산개되어 있음

작은 프로덕트 먼저 만들어서 기능 확인하는게 먼저인듯
