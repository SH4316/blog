예) `@JdbcTypeCode(SqlTypes.CHAR)`

### columnDefinition 과 차이
`@Column`의 `columnDefinition` : SQL Type 정의
`@JdbcTypeCode` : Hibernate 가 어떤 Mapping 을 사용할지 명시적으로 결정

### 주의할점
`SqlTypes`는 SQL 타입을 지정함
```
SQL Type <-> Java Object
```

예)
```
@JdbcTypeCode(SqlTypes.CHAR)
private UUID id;
```
-> DB 에는 Char 로 저장되고
-> Object 는 UUID 로 활용된다


### Convert Architecture
3가지 요소의 Registry
- `JdbcTypeRegistry`
- `JavaTypeRegistry`
- `BasicTypeRegistry`

##### BasicType
`BasicType` : `JdbcType`와 `JavaType` 를 연결해주는 역할

`JavaType`, `JdbcType` 조합을 조회 또는 생성함 (생성 프로세스는 잘 모르겠음)

`BasicType`이 `ValueBinder`와 `ValueExtractor`를 소유
##### 동작
- `JavaType.wrap()`
- `JavaType.unwrap()`

- `ValueBinder` : Java Object -> preparedStatement
- `ValueExtractor` : JDBC ResultSet -> Java Object

- `JavaType.unwrap()` + `ValueBinder` : SQL로 저장
- `ValueExtractor` + `JavaType.wrap()` : SQL로 읽기

### 예시
`jsonb(sql)` 을 `Map<Object, Object>`로 매핑 -> `@JdbcTypeCode(SqlTypes.JSON)`
